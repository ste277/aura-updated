# R2D-02: Tier 1 Mandatory Controls: Implementation Specification

**Every Tier 1 control must be implemented in the harness, self-tested without real keychain reads (mocks), and independently reviewed BEFORE any prototype execution. Any failed Tier 1 preflight means NO-GO:** the harness exits before creating anything.

| ID | Control | Implementation | Verification (reviewable) | NO-GO if |
|---|---|---|---|---|
| **T1-1** | Reject if the dedicated keychain is in the search list or is the default | Read-only queries `security list-keychains -d user|dynamic|common|system` and `security default-keychain -d user|system`, captured as the baseline. The prototype path must be absent from all of them before creation, after every step, and at teardown. The baseline must be byte-identical at the end | Self-test with a mock `list-keychains` output that contains the path, which must give NO-GO | the path is present in any domain; the default ≠ login; any change from the baseline |
| **T1-2** | ACL inspection with trusted-application identity, before and after | `security dump-keychain -a <path>` parsed **per record** (reset on `^keychain:`), requiring **both** `"acct"<blob>="<acct>"` and `"svce"<blob>="<svc>"`. The `decrypt` entry's `applications (N)` **and** every following `requirement:` / path line are captured. More than one matching record means OPEN(duplicate). **Caveat:** whether `dump-keychain -a` on a **locked** keychain raises an unlock dialog is **unknown**, so ACL reads happen **only inside a controlled unlocked window** until L1 proves otherwise | Self-tests with recorded dump fixtures: `(0)` → restricted; `(1)` + `com.apple.security` → OPEN + identity; decoy account → ignored; duplicate → OPEN | item A ≠ `applications (0)` at preflight; any unexpected trusted identity at any point (item B's expected creator identity is whitelisted **only** for item B) |
| **T1-3** | Passphrase custody: no clipboard, echo, source code or logging | See R2D-05. The harness **never** reads the passphrase itself if `security` can prompt on the tty: `create-keychain` / `unlock-keychain` **without `-p`** (interactive tty prompt; **UNVERIFIED**: confirm the prompt behaviour in the harness self-test on a throwaway keychain **only after execution approval**). Fallback (or drop it): `read -s` from `/dev/tty`. The charset is restricted to `^[a-z]+( [a-z]+)*$`; the value is passed **only** as `builtin print -r -- "<command with quoted passphrase>" | security -i >/dev/null 2>&1`, then cleared. **`builtin print -r` into that pipe is the single permitted use.** Terminal → **Secure Keyboard Entry ON** during any tty entry | Code review: no `-p` in argv; no echo; `print -r` never used on the variable; logs scanned for the variable (self-test with a mock passphrase) | any code path places the passphrase in argv, env, a file, the clipboard or a log |
| **T1-4** | Launcher SHA-256 recorded and verified | The **bootstrap** (R2D-06) computes the sha256 of the **exact bytes it will execute** and compares them with the owner-supplied expected hash. The harness logs that hash as its first log line | Self-test: a one-byte change to the file gives a bootstrap refusal | mismatch; missing expected hash |
| **T1-5** | No launcher substitution between check and run (TOCTOU) | **Hash-then-execute-from-memory:** the bootstrap reads the file **once** into memory, hashes **those bytes**, and executes **those same bytes** (`zsh -f -c "$S"`), so the file is never reopened. System binaries `/bin/zsh`, `/usr/bin/security`, `/usr/bin/shasum` and `/bin/ps` are SIP-protected (record `csrutil status` = enabled; read-only command). No other script files are sourced | Self-test: modifying the file **after** the bootstrap's read doesn't change what runs (an injected marker never appears) | SIP not enabled; the harness sources any external file |
| **T1-6** | Accessibility / UI automation disabled | (a) **Owner attestation:** **every** Accessibility toggle OFF (claude, Claude, Codex Computer Use, ISL Online Agent, Splashtop, Terminal, Zoom), **and** System Settings → General → Sharing: Screen Sharing, Remote Management and Remote Login OFF. Note: Terminal in Accessibility would let any Terminal-launched process script dialogs. (b) Harness process check by **executable name** via `ps -axo pid=,ppid=,comm=`, **excluding the harness PID and its recorded children** (review P1-2: `pgrep -f` self-matches subshells). Refuse if any of these run: `cua_node`, Codex Computer Use, ChatGPT, Claude / Claude Helper / `claude` (Claude Code), `zoom.us`, Splashtop, ISL Online, SuperOps, TeamViewer, AnyDesk, RustDesk, ScreenConnect, `screensharingd`, ARDAgent, Hammerspoon, Keyboard Maestro, BetterTouchTool, `osascript`. (c) The owner confirms no remote-support session is active. TCC can't be read programmatically here (authorization denied), so (a) is mandatory | Self-test with a mock process list containing `cua_node`, which must give NO-GO | any attestation `n`; any listed process running |
| **T1-8** | **Keychain-path guard** (review P2-2) | every `security` call that accepts a keychain argument must carry a **non-empty** `$KC` matching `$TMPDIR/r2d-run.*/r2d.keychain-db`. `unlock-keychain`, `lock-keychain` and `set-keychain-settings` with no argument would target the **login keychain** | mock self-test with `KC=''`, which must give NO-GO before any `security` call | empty or mismatching `$KC` |
| **T1-9** | **SIP** | `csrutil status` must equal exactly `System Integrity Protection status: enabled.`; reject "Custom Configuration" | self-test with a mock output | anything else |
| **T1-7** | Deterministic cleanup and recovery | See R2D-07: an idempotent teardown on EXIT, INT, TERM and HUP; reaping recorded child PIDs only (ppid-checked); cancelling the watchdog; lock; delete; verify; `CLEANUP: VERIFIED` or `UNVERIFIED` + manual steps | Self-tests: normal, STOP, Ctrl-C, injected error, idempotency | — (an unverified cleanup gives HOLD and recovery steps) |

**Additional Tier 1 carry-overs** (from R2B/R2B-6 hardening; mandatory):
- **Input:** single-token validated answers; type-ahead flushed; EOF and whitespace are never confirmation; invalid input never logged.
- **Results before questions:** results logged **before** any owner question.
- **Owner-only artifacts:** `umask 077`; logs 0600.
- **Disk:** ≥ 500 MB free.
- **Locking:** a lock directory prevents concurrent runs.
- **Evidence header:** the log records macOS version, `csrutil status` and the harness hash.
